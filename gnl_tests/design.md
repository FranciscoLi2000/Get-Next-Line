# Get Next Line 实现设计

## 总体策略

Mandatory 版本使用一个 `static char *stash` 保存当前 fd 尚未返回的残留数据。每次调用先检查缓存中是否已有换行；若没有，则按 `BUFFER_SIZE` 分块 `read`，追加到缓存，直到发现换行或 `read` 返回 0 / -1。随后从缓存中提取一行（包含换行），并将剩余内容重新保存为新的缓存。错误路径会释放缓存并返回 `NULL`，避免泄漏。

## 工具函数

`get_next_line_utils.c` 只实现项目所需的最小工具：字符串长度、换行查找、带边界保护的拼接、按长度复制。不能使用 libft，因此这些函数全部独立实现。

## Bonus 策略

Bonus 版本只使用一个 static 指针变量，即 `static t_fdlist *fds`。链表每个节点保存一个 fd 及其独立缓存。每次调用先查找或创建对应 fd 节点；读取、提取和更新都只作用于该节点。若某个 fd 到达 EOF 或发生错误且缓存为空，则从链表中删除该节点并释放其内容。这样可以用一个 static 变量同时管理多个文件描述符。

## 边界与测试

测试将覆盖 `BUFFER_SIZE=1, 42, 9999`；空文件；只有换行；无结尾换行；连续换行；超长行；stdin 管道；无效 fd；以及 bonus 的 3 个 fd 交错读取。所有动态分配路径通过 Valgrind 检查。
